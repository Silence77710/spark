# Spark 工程文档

本目录是 Spark 项目的工程级文档集中地，与代码同源维护，作为业务规格、数据模型、API 契约、部署流程的"唯一可信来源"。

## 文档清单

| 文档 | 作用 | 何时更新 |
|------|------|---------|
| [业务.md](./业务.md) | 业务文档：领域对象、用户场景、核心流程、状态机 | 业务规则、核心流程变化时 |
| [接口.md](./接口.md) | 接口文档：HTTP API 的契约、参数、响应、错误码 | 新增 / 修改 / 删除接口时 |
| [数据模型.md](./数据模型.md) | 数据模型附录：所有表的字段、类型、约束、枚举值 | 数据表 schema 变化时 |
| [变更日志.md](./变更日志.md) | 变更日志：版本、变更类型、影响范围、迁移说明 | 每次发版或合并到主干的提交 |
| [部署.md](./部署.md) | 部署文档：环境、构建、Docker、数据库迁移、上线、回滚 | 部署链路、镜像、依赖、运维变更时 |

## 与根目录文档的关系

根目录的 `AGENTS.md` / `PRODUCT.md` / `SPEC.md` / `PRD-AI.md` 仍为产品层文档。
`docs/` 内的工程文档聚焦"怎么交付"：

- `AGENTS.md` 定义 AI 编码规范与项目元信息。
- `PRODUCT.md` / `SPEC.md` / `PRD-AI.md` 定义"做什么"。
- `docs/` 定义"做了什么、怎么对外交付"。

## 维护原则

1. **代码或业务变更，必须在同一次 PR 中同步更新受影响的文档**——不一致视为缺陷（详见 `AGENTS.md`「文档同步」硬规则）。
2. **API 文档是契约**：任何被前端或外部调用方使用的接口，必须在 `API.md` 中登记后再合并。
3. **变更日志 必须可追溯**：每次合并到 `main` 的提交，需要追加一行变更记录。
4. **部署文档随环境走**：构建参数、镜像标签、环境变量、迁移脚本的变化都必须落到 `部署.md`。

## 阅读顺序建议

- 新加入项目：根 README.md → AGENTS.md → PRODUCT.md → docs/业务.md → docs/接口.md → docs/数据模型.md → docs/架构.md → docs/部署.md
- 接手一个需求：docs/接口.md → SPEC.md → 源码
- 准备上线：docs/变更日志.md → docs/部署.md → docs/规范.md
