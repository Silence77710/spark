# Spark 业务文档

> 面向开发者与协作方的"业务全景图"——讲清楚 Spark 是什么、解决什么问题、领域对象怎么流转、关键状态如何变化。
>
> 本文档与 `PRODUCT.md`（产品定义）、`SPEC.md`（V1 规格）、`PRD-AI.md`（AI 模块 PRD）形成阶梯：
> 本文档讲"业务骨架"，产品层文档讲"功能细节"。

## 一、产品定位（一句话）

Spark 是一款帮你捕捉、孵化、连接想法，最终把想法变成现实的思想操作系统。

更具体地说，它不是笔记、不是 Todo、不是项目管理，而是一座思想花园：让想法自然生长，并定期回看、嫁接、最终落地。

## 二、用户与场景

### 2.1 唯一用户：你（创作者）

Spark 假设只有"想法的产出者 + 培育者 + 实现者"这一类用户，无团队、无协作、无外部共享。所有功能都建立在"个人使用"假设之上。

### 2.2 核心场景

| 场景 | 描述 | Spark 提供的关键能力 |
|------|------|---------------------|
| 闪电捕获 | 灵感转瞬即逝，需要零摩擦录入 | Capture Box、Markdown |
| 想法孵化 | 想法需要被结构化、补充状态与重要度 | 状态机、Importance、集合 |
| 想法回望 | 想法不浇水就死，需要定期被温柔提醒 | Rhythm 页、回访时间线 |
| 想法杂交 | 好的想法诞生于两个想法的交叉点 | Hybrid Catalyst、Relationships |
| 想法接生 | 想法被淘汰或长眠时，需要被记录 | 墓地（Graveyard）、墓志铭 |
| AI 思考伙伴 | 镜子式反馈、提问、挑战、翻译、连接 | 12 类 AI 功能 |

## 三、领域对象

### 3.1 想法（Idea）

最核心的领域对象，对应表 `ideas`。字段含义：

| 字段 | 含义 | 取值 |
|------|------|------|
| `id` | 主键，UUID | 36 位字符串 |
| `title` | 标题，必填 | 最长 500 字 |
| `content` | 正文，Markdown | TEXT，可空 |
| `status` | 状态 | seed / sprout / growing / realized / archived / dormant |
| `collection` | 集合（用户自填分类） | VARCHAR，可空 |
| `importance` | 重要度（0-4） | 数字 0-4，标签由 settings.importance_levels 决定 |
| `is_capsule` | 是否时间胶囊 | 布尔 |
| `unlock_at` | 解锁时间 | DATETIME(3) |
| `parent_a_id` / `parent_b_id` | 杂交父本（最多 2 个） | 关联 ideas.id |
| `epitaph` | 墓志铭 | TEXT，进入归档/休眠时填写 |
| `emotion` | 捕获时情绪 | excited / curious / anxious / calm / confused |
| `created_at` / `updated_at` | 创建与更新时间 | DATETIME(3) |
| `last_reviewed_at` | 最近一次回访时间 | DATETIME(3) |

### 3.2 想法活动时间线（IdeaActivity）

对应表 `idea_activities`。每个想法都有一条"成长日记"，自动记录关键事件：

| type | 含义 | 触发时机 |
|------|------|---------|
| `capture` | 捕获 | 创建想法时 |
| `status_change` | 状态变化 | PATCH 修改 status |
| `importance_change` | 重要度变化 | PATCH 修改 importance |
| `emotion` | 情绪记录 | 用户记录当前情绪 |
| `general` | 通用事件 | 杂交诞生、墓志铭等 |

### 3.3 想法关联（IdeaRelationship）

对应表 `idea_relationships`。记录两个想法之间的语义连接：

- `type`：`related`（普通相关）/ `inspires`（A 启发 B）/ `evolved`（演化自）
- `created_by`：`user`（用户手动）/ `ai`（AI 连接器推荐）
- `ai_explanation`：AI 推荐时附带的解释

### 3.4 AI 分析存档（IdeaAnalysis）

对应表 `idea_analyses`。`/api/ai/analyze` 只生成不存，**用户确认后才入库**——保留历史分析，可对比。

### 3.5 AI 交互日志（AiInteraction）

对应表 `ai_interactions`。每次 AI 调用都记录 feature、tokens、摘要，用于"隐私控制"页提供透明日志。

### 3.6 集合（Collection）

集合不是独立表，是 `ideas.collection` 字段的去重统计。命名空间由用户自填；`/api/collections` 提供列表/重命名/删除。

### 3.7 设置（Setting）

键值对表 `settings`，存储：

- `importance_levels`：5 级重要度标签（默认 `DEFAULT_IMPORTANCE_LEVELS`）
- `ai_enabled`：是否启用 AI
- `ai_features`：10 类 AI 功能的开关矩阵


## 四、状态机

### 4.1 想法状态（Idea Status）

```
seed ──► sprout ──► growing ──► realized
                         │
                         ├──► archived（墓志铭 epitaph）
                         └──► dormant（可被唤醒）
```

| 状态 | 含义 | 进入条件 | 离开条件 |
|------|------|---------|---------|
| seed | 刚捕获的种子 | 创建即进入 | 用户开始整理、补充内容 → sprout |
| sprout | 萌芽，开始生长 | 用户首次编辑内容 | 持续投入 → growing |
| growing | 生长中，正在被认真对待 | 用户多次编辑或回访 | 实现 → realized / 放弃 → archived |
| realized | 已实现，落地为现实 | 用户标记完成 | 沉淀保留 |
| archived | 主动归档 | 用户标记归档，可填墓志铭 | 沉淀保留 |
| dormant | 休眠（被动） | 用户标记休眠 | 可重新激活为 growing |

### 4.2 状态变化触发记录

每次 status 变化都会写一条 `idea_activities`（type=`status_change`），文案形如 `状态从「萌芽」变为「生长中」`。

### 4.3 重要度等级

`importance` 是数字 0-4，对应 `settings.importance_levels` 配置的标签。默认标签为：

```
0: 暂存     1: 一般     3: 重要     4: 关键
（2 留给自定义位）
```

> 注：实际默认标签见 `packages/@spark/utils/src/importance.ts` 的 `DEFAULT_IMPORTANCE_LEVELS`，本表仅展示结构。

## 五、核心流程

### 5.1 闪电捕获流程

```
用户在 Capture Box 输入标题（必填）+ 内容（可选）+ 情绪（可选）
   │
   ▼
POST /api/ideas  →  生成 id → 插入 ideas(status=seed)
   │
   ▼
自动写入 idea_activities(type=capture)  →  列表页刷新
```

零摩擦原则：捕获时**不要求**填分类、标签、优先级，只记录情绪（选填）。

### 5.2 想法杂交流程（Hybrid Catalyst）

```
用户选两个想法 A、B → POST /api/ideas { parent_a_id, parent_b_id }
   │
   ▼
生成新想法 C（status=seed），同时写 idea_activities(type=general)：「从「A」和「B」杂交诞生」
   │
   ▼
AI 可选：对 C 做全方位分析 → 用户确认 → POST /api/ideas/[id]/analyses 存档
```

### 5.3 想法连接器（Connection Maker）

```
用户点击「发现连接」 → POST /api/ai/connect
   │
   ▼
后端拉取非归档/休眠的最近 50 条想法 → 送入 AI 推理
   │
   ▼
返回 pairs: [{ source_id, target_id, explanation }]  → 用户确认
   │
   ▼
POST /api/relationships { ..., created_by: "ai" }  → 落地
```

### 5.4 回望流程（Retro）

- `/retro` 页面提供每日/每周回望：调出今天/本周更新的想法 + AI 生成回望总结。
- `last_reviewed_at` 由用户在回望页手动更新。

### 5.5 想法墓地（Graveyard）

- `/graveyard` 列出 status IN (archived, dormant) 的想法。
- 用户可编辑墓志铭（`epitaph`），自动写 `idea_activities`。

## 六、AI 思考伙伴矩阵

PRD-AI.md 详细描述每个 AI 功能的提示词与交互。本节给出**面向业务的功能矩阵**：

| 功能 | 入口路径 | 入口 API | 入库行为 |
|------|---------|---------|---------|
| 镜子（Mirror） | /rhythm | /api/ai/mirror | 写 ai_interactions |
| 苏格拉底（Socratic） | /ideas/[id] | /api/ai/socratic | 写 ai_interactions |
| 连接器（Connector） | /explore | /api/ai/connect | 写 ai_interactions + 用户确认后写 idea_relationships |
| 杂交催化剂（Catalyst） | /ideas/[id] | /api/ai/catalyst | 用户确认后写 ideas(parent_a_id/parent_b_id) |
| 翻译（Translate） | /ideas/[id] | /api/ai/translate | 写 ai_interactions |
| 辩手（Devil's Advocate） | /ideas/[id] | /api/ai/devil | 写 ai_interactions |
| 验尸官（Coroner） | /graveyard | /api/ai/coroner | 写 ai_interactions |
| 盲点（Blindspot） | /ideas/[id] | /api/ai/blindspot | 写 ai_interactions |
| 思考画像（Profile） | /profile | /api/ai/profile | 写 ai_interactions |
| 回望对话（Retro） | /retro | /api/ai/retro | 写 ai_interactions |
| 全方位分析（Analyzer） | /ideas/[id] | /api/ai/analyze | 写 ai_interactions + 用户确认后写 idea_analyses |

> 共同特征：所有 AI 调用经 `packages/@spark/ai` 的进程内串行队列，429/5xx/网络错误自动重试 ≤2 次。

## 七、非功能性约束

1. **本地优先**：MySQL 数据存本机 spark-mysql 容器，零云依赖。
2. **AI 可降级**：未配 `AI_API_KEY` 时 AI 功能静默不可用，其余功能不受影响。
3. **隐私透明**：`ai_interactions` 完整记录每次 AI 调用，用户可在设置页查看/清除。
4. **无认证**：V1 假设单机单用户，未引入登录与权限。
