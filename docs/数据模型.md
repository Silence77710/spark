# API 字段定义（附录）

> 本文档是 [`API.md`](./API.md) §9 的字段定义附录。任何字段类型、枚举值、约束的变更必须同 PR 提交并在此更新。
>
> 数据表定义以 [`packages/@spark/db/schema.sql`](../packages/%40spark/db/schema.sql) 为权威来源。

## 一、Idea（想法）

数据表：`ideas`

| 字段 | 类型 | 必填 | 约束 / 取值 |
|------|------|------|------------|
| id | VARCHAR(36) | 是 | 主键，UUID |
| title | VARCHAR(500) | 是 | 标题，去前后空格 |
| content | TEXT | 否 | Markdown 正文 |
| status | VARCHAR(20) | 是 | seed / sprout / growing / realized / archived / dormant，默认 seed |
| collection | VARCHAR(100) | 否 | 集合名 |
| importance | TINYINT | 是 | 0-4，默认 0；范围由 `settings.importance_levels` 决定 |
| is_capsule | BOOLEAN | 是 | 是否时间胶囊，默认 false |
| unlock_at | DATETIME(3) | 否 | 时间胶囊解锁时间 |
| epitaph | TEXT | 否 | 墓志铭（归档/休眠时填写） |
| parent_a_id | VARCHAR(36) | 否 | 杂交父本 A，FK→ideas.id |
| parent_b_id | VARCHAR(36) | 否 | 杂交父本 B，FK→ideas.id |
| emotion | VARCHAR(20) | 否 | excited / curious / anxious / calm / confused |
| created_at | DATETIME(3) | 是 | 创建时间 |
| updated_at | DATETIME(3) | 是 | 更新时间 |
| last_reviewed_at | DATETIME(3) | 否 | 最近回访时间 |

## 二、IdeaActivity（活动）

数据表：`idea_activities`

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| id | VARCHAR(36) | 是 | 主键 |
| idea_id | VARCHAR(36) | 是 | FK→ideas.id ON DELETE CASCADE |
| type | VARCHAR(20) | 是 | capture / status_change / importance_change / emotion / general |
| content | TEXT | 是 | 人类可读文案 |
| created_at | DATETIME(3) | 是 | 时间 |

索引：`idx_idea_activities_idea_id`

## 三、IdeaRelationship（关联）

数据表：`idea_relationships`（无 FK，仅索引）

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| id | VARCHAR(36) | 是 | 主键 |
| source_id | VARCHAR(36) | 是 | 源想法 |
| target_id | VARCHAR(36) | 是 | 目标想法 |
| type | VARCHAR(20) | 是 | related / inspires / evolved，默认 related |
| created_by | VARCHAR(10) | 是 | user / ai |
| ai_explanation | TEXT | 否 | AI 推荐理由 |
| created_at | DATETIME(3) | 是 | 时间 |

索引：`idx_rel_source`、`idx_rel_target`

## 四、IdeaAnalysis（分析存档）

数据表：`idea_analyses`（无 FK，仅索引）

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| id | VARCHAR(36) | 是 | 主键 |
| idea_id | VARCHAR(36) | 是 | 关联想法 |
| dimensions | JSON | 是 | `[{name: string, content: string}, ...]`，POST 时需通过 `validateDimensions` |
| model | VARCHAR(100) | 否 | 使用的模型 |
| tokens_used | INT | 否 | 消耗 token |
| created_at | DATETIME(3) | 是 | 时间 |

索引：`idx_idea_analyses_idea_id`

## 五、Setting（设置）

数据表：`settings`（键值对）

| key | value 类型 | 默认值 | 说明 |
|-----|-----------|--------|------|
| importance_levels | JSON 字符串 | `DEFAULT_IMPORTANCE_LEVELS` | 5 项 `{value, label}` 数组 |
| ai_enabled | "true"/"false" | "false" | 是否启用 AI |
| ai_features | JSON 字符串 | `DEFAULT_AI_FEATURES_FULL` | 10 类 AI 功能开关矩阵 |

## 六、Collection（集合）

非独立表，是 `ideas.collection` 的去重统计，由 `GET /api/collections` 返回 `[{name, count}]`。

## 七、AiInteraction（AI 交互日志）

数据表：`ai_interactions`

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| id | VARCHAR(36) | 是 | 主键 |
| feature | VARCHAR(30) | 是 | 路由名（analyze/socratic/connector/catalyst/devil/translate/coroner/mirror/profile/retro/blindspot） |
| idea_id | VARCHAR(36) | 否 | 关联想法 |
| request_summary | VARCHAR(200) | 否 | 请求摘要 |
| response_summary | VARCHAR(500) | 否 | 响应摘要 |
| tokens_used | INT | 否 | 消耗 token |
| created_at | DATETIME(3) | 是 | 时间 |

索引：`idx_ai_interactions_idea_id`

## 八、枚举值速查

### 8.1 想法状态 status

```
seed      → 种子
sprout    → 萌芽
growing   → 生长中
realized  → 已实现
archived  → 已归档（带墓志铭）
dormant   → 休眠（可被唤醒）
```

### 8.2 情绪 emotion

```
excited   → 兴奋
curious   → 好奇
anxious   → 焦虑
calm      → 平静
confused  → 困惑
```

### 8.3 关联 type

```
related   → 普通相关
inspires  → 启发
evolved   → 演化自
```

### 8.4 关联 created_by

```
user  → 用户手动
ai    → AI 连接器推荐
```

### 8.5 AI 功能 feature

```
analyzer      → 全方位分析
socratic      → 苏格拉底追问
connector     → 连接器
catalyst      → 杂交催化剂
devil         → 辩手
translate     → 翻译
coroner       → 验尸官
mirror        → 镜子
profile       → 思考画像
retro         → 回望对话
blindspot     → 盲点
```

## 九、跨表约束

- `idea_activities.idea_id` ON DELETE CASCADE：删除想法时活动一并删除。
- `idea_relationships` / `idea_analyses` / `ai_interactions` **不**加 FK：线上库 `ideas` 表为 `utf8mb4_0900_ai_ci`，与 schema 文件声明的 `unicode_ci` 不一致，加 FK 会触发 MySQL 3780 错误。孤儿数据通过应用层校验防止（见 `POST /api/ideas/[id]/analyses` 等）。
