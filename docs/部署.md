# Spark 打包与部署文档

> 本文档面向运维与发布：覆盖**环境、构建、Docker 镜像、数据库迁移、上线、回滚、故障排查**全链路。
>
> 适用的部署拓扑：单机 Docker（本地开发 / 自部署）。多机 / K8s 部署以本文档为基础自行扩展。

## 一、环境要求

### 1.1 运行时版本

| 组件 | 版本 | 说明 |
|------|------|------|
| Node.js | ≥ 20（推荐 22） | 与 `package.json` 的 `engines.node` 一致；Dockerfile 使用 `node:22-slim` |
| pnpm | 10.33.0 | 通过 `corepack` 启用；与 `apps/web/package.json` 的 `packageManager` 锁版本一致 |
| MySQL | 8.x | utf8mb4 字符集；线上库为 `utf8mb4_0900_ai_ci` |
| Docker | ≥ 24 | 本地镜像构建与运行 |
| 磁盘 | ≥ 5 GB 可用 | monorepo + node_modules + .next 产物 |

### 1.2 网络端口

| 端口 | 用途 | 备注 |
|------|------|------|
| 3000 | Spark Web | Next.js standalone 容器 |
| 3306 | MySQL | 仅本机或可信网络暴露 |

### 1.3 目录约定

```
spark/
├── Dockerfile                    # 镜像构建入口
├── .dockerignore                 # 构建排除
├── apps/web/                     # Next.js 应用
│   └── .next/standalone/         # 构建产物（运行时镜像仅拷此目录）
├── packages/@spark/db/schema.sql # 数据库初始化脚本
└── docs/部署.md            # 本文档
```

## 二、本地开发

### 2.1 启动 MySQL（Docker）

```bash
docker run -d --name spark-mysql \
  -p 3306:3306 \
  -e MYSQL_ROOT_PASSWORD=spark123 \
  -e MYSQL_DATABASE=spark \
  mysql:8 \
  --character-set-server=utf8mb4 \
  --collation-server=utf8mb4_0900_ai_ci
```

> 首次启动 / 重建容器后执行 schema：
>
> ```bash
> docker exec -i spark-mysql mysql -uroot -pspark123 < packages/@spark/db/schema.sql
> ```

### 2.2 安装与启动 Next.js

```bash
pnpm install
cp .env.example apps/web/.env.local  # 按需填入 AI_API_KEY
pnpm dev  # http://localhost:3000
```

## 三、构建产物

### 3.1 Next.js standalone 构建

```bash
pnpm --filter @spark/web build
```

输出在 `apps/web/.next/standalone/`，仅含运行所必需的最小依赖树。`outputFileTracingRoot` 已设为 monorepo 根，跨包依赖能被打进产物。

### 3.2 静态资源

构建后以下两份需要随镜像分发：

- `apps/web/.next/static/` → 静态资产（JS/CSS/图片等），挂到 `apps/web/.next/static`
- `apps/web/public/` → 公共文件，挂到 `apps/web/public`

`Dockerfile` 的 `runner` 阶段已自动处理这两个目录的 COPY。

### 3.3 产物自检

构建完成后最小自检：

```bash
test -f apps/web/.next/standalone/apps/web/server.js \
  && echo "✅ standalone 构建成功" \
  || echo "❌ 缺少 server.js，请检查 next.config.ts 的 output: standalone"
```

## 四、Docker 镜像

### 4.1 构建

```bash
docker build -t spark-web:local .
```

> 镜像分两阶段：
> - `builder`：安装依赖 + `pnpm --filter @spark/web build`，依赖走 `--mount=type=cache` 复用 `pnpm-store`。
> - `runner`：仅拷 standalone + static + public；以非 root 用户 `spark` 运行。

### 4.2 运行

```bash
docker run -d --name spark-web \
  -p 3000:3000 \
  -e MYSQL_HOST=host.docker.internal \
  -e MYSQL_PORT=3306 \
  -e MYSQL_USER=root \
  -e MYSQL_PASSWORD=spark123 \
  -e MYSQL_DATABASE=spark \
  -e AI_API_KEY=<your-key> \
  -e AI_BASE_URL=https://tokens.store/v1 \
  -e AI_MODEL=deepseek-v4-flash \
  spark-web:local
```

> 在 macOS / Windows 上，`host.docker.internal` 直接指向宿主机的 MySQL。
> Linux 上需加 `--add-host=host.docker.internal:host-gateway` 或改用宿主机内网 IP。

### 4.3 镜像标签规范

| 环境 | 标签示例 |
|------|---------|
| 本地 | `spark-web:local` |
| 开发 | `spark-web:dev-<sha7>` |
| 预发 | `spark-web:staging-<sha7>` |
| 生产 | `spark-web:v0.1.0-<sha7>` |

> 严禁使用 `latest` —— 不可追溯，且无法回滚到具体版本。


## 五、环境变量

所有环境变量放在 `apps/web/.env.local`（已被 `.gitignore`，不进版本库）。模板在仓库根 `.env.example`。

### 5.1 必需

| 变量 | 必填性 | 说明 |
|------|--------|------|
| `AI_API_KEY` | **业务必需** | OpenAI 兼容接口的 key。无硬编码兜底，未配置时 AI 路由静默不可用 |
| `MYSQL_HOST` | 否 | 默认 `127.0.0.1` |
| `MYSQL_PORT` | 否 | 默认 `3306` |
| `MYSQL_USER` | 否 | 默认 `root` |
| `MYSQL_PASSWORD` | 否 | 默认 `spark123` |
| `MYSQL_DATABASE` | 否 | 默认 `spark` |

### 5.2 可选

| 变量 | 默认 | 说明 |
|------|------|------|
| `AI_BASE_URL` | `https://api.openai.com/v1` | OpenAI 兼容接口 base URL |
| `AI_MODEL` | （空） | 模型标识，写入 `ai_interactions.model` 用于审计 |
| `NODE_ENV` | `production` | 容器内已固定 |
| `PORT` | `3000` | Next.js 监听端口 |
| `HOSTNAME` | `0.0.0.0` | 监听地址，容器内已固定 |

### 5.3 密钥注入建议

- **禁止**把 `.env.local` 拷进镜像。
- 生产环境用 Docker `--env-file` / Kubernetes `Secret` / Vault 等机制注入。
- CI 流水线中密钥走 secret manager，**严禁**出现在日志或镜像层。

## 六、生产部署

### 6.1 拓扑

```
                      ┌──────────────┐
                      │  Reverse     │  :443（TLS）
                      │  Proxy       │  nginx / Caddy
                      └──────┬───────┘
                             │
                             ▼  :3000
                      ┌──────────────┐
                      │  spark-web   │  Next.js standalone
                      │  (Docker)    │
                      └──────┬───────┘
                             │
                             ▼  :3306
                      ┌──────────────┐
                      │  spark-mysql │  MySQL 8
                      │  (Docker)    │
                      └──────────────┘
```

### 6.2 反向代理（nginx 示例）

```nginx
server {
  listen 443 ssl http2;
  server_name spark.example.com;

  ssl_certificate     /etc/ssl/spark.crt;
  ssl_certificate_key /etc/ssl/spark.key;

  client_max_body_size 4m;        # 想法正文通常很小

  location / {
    proxy_pass http://127.0.0.1:3000;
    proxy_http_version 1.1;
    proxy_set_header Host              $host;
    proxy_set_header X-Real-IP         $remote_addr;
    proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_read_timeout 90s;           # AI 路由可能较慢
  }
}
```

### 6.3 防火墙

- 公网**只暴露 443**。
- MySQL 仅允许 spark-web 容器所在网络访问（用 docker network 隔离）。
- SSH 端口按需限制来源 IP。

## 七、健康检查

### 7.1 容器健康

`spark-web` 容器**建议**加入：

```bash
docker run --health-cmd "wget -qO- http://127.0.0.1:3000/ || exit 1" \
           --health-interval 30s \
           --health-timeout 5s \
           --health-retries 3 \
           --health-start-period 20s \
           ...
```

### 7.2 应用健康

`/` 路由返回 200 即视为就绪。AI 路由**不**作为健康判据（外部依赖波动不应触发容器重启）。

### 7.3 MySQL 健康

```bash
docker exec spark-mysql mysqladmin ping -uroot -pspark123
```

## 八、数据库迁移

### 8.1 初始化（首次）

```bash
docker exec -i spark-mysql mysql -uroot -pspark123 < packages/@spark/db/schema.sql
```

`schema.sql` 中所有表均用 `CREATE TABLE IF NOT EXISTS`，可重复执行。

### 8.2 schema 变更

- 表结构变更写到 `packages/@spark/db/schema.sql`，**同时**同步 `docs/数据模型.md`。
- 在 变更日志 中标注 `breaking` / `feat(db)`。
- V1 阶段**不**保留历史 migration 文件，schema 文件本身即历史（创建/重建脚本合一）。
- V2 起迁移到 `migrations/` 目录（带版本号），并改造 schema.sql 为最新视图。

### 8.3 备份与恢复

```bash
# 备份
docker exec spark-mysql sh -c 'mysqldump -uroot -pspark123 spark' > backup-$(date +%Y%m%d-%H%M%S).sql

# 恢复（注意：会清空现有 spark 库）
docker exec -i spark-mysql mysql -uroot -pspark123 < backup-20260821-103000.sql
```

> 备份策略建议：本地开发每周一次；生产按数据量与重要性选择日备 / 小时级 binlog。

## 九、升级与回滚

### 9.1 升级步骤

1. 拉取新镜像：`docker pull spark-web:v0.2.0-<sha7>`
2. 停止旧容器：`docker stop spark-web && docker rm spark-web`
3. 启动新容器（保持同一 `--name` 与端口映射）：
   ```bash
   docker run -d --name spark-web -p 3000:3000 \
     -e MYSQL_HOST=... -e AI_API_KEY=... \
     spark-web:v0.2.0-<sha7>
   ```
4. 验证：检查 `/` 返回 200、检查 `docker logs spark-web` 无报错。
5. 在 `docs/变更日志.md` 标注发布版本号。

### 9.2 回滚

回滚 = 启动上一个已验证镜像版本（参考 §9.1 步骤 2-4）。数据向后兼容即可；如不兼容，按 §10.2 处理。

### 9.3 不兼容升级（breaking）

涉及 schema 不兼容的升级：

1. 先备份（§8.3）。
2. 部署新应用，禁用写入或读双写。
3. 执行数据迁移脚本。
4. 切流量到新应用。
5. 保留旧版本镜像 ≥ 7 天再清理。

## 十、故障排查

### 10.1 容器启动后立刻退出

```bash
docker logs spark-web --tail 50
```

常见原因：

- 缺少 `MYSQL_HOST` → 报 `ECONNREFUSED`
- `MYSQL_PASSWORD` 错误 → 报 `Access denied`
- `schema.sql` 未执行 → 报 `Table 'spark.ideas' doesn't exist`

### 10.2 AI 路由 502 / 超时

`packages/@spark/ai` 内置串行队列 + 重试，单次最多 2 次。仍失败的可能原因：

- 上游 429 限流持续（已重试后仍 429）→ 调整调用频率
- `AI_API_KEY` 无效 → `/api/settings` 中 `ai_enabled=false` 可临时关闭 AI

### 10.3 MySQL 连接池耗尽

`getDb` / `releaseDb` 必须成对出现。HTTP 路由在 `try {} finally { releaseDb(conn) }` 中释放。如出现 `PoolExhausted`：

1. 检查是否有 `finally` 缺失的路由
2. 临时调大 `connectionLimit`（`packages/@spark/db/src/index.ts`）

### 10.4 构建失败

```bash
# 清缓存重试
rm -rf node_modules apps/*/node_modules packages/*/node_modules
pnpm install
pnpm --filter @spark/web build
```


## 十一、监控与日志

### 11.1 应用日志

容器默认 stdout 输出，`docker logs spark-web` 即可查看。建议部署侧接：

- macOS / Linux：`docker logs -f spark-web 2>&1 | tee -a /var/log/spark/web.log`
- 生产：用 journald / Promtail / Fluent Bit 等转给 Loki / ELK。

AI 路由失败日志形如 `[ai/socratic] request failed: ...`，grep 关键词 `request failed` 快速定位。

### 11.2 关键指标（自检）

| 指标 | 来源 | 健康区间 |
|------|------|---------|
| 进程存活 | 容器 healthcheck | 持续 RUNNING |
| HTTP 200 比例 | 反向代理 access log | ≥ 99% |
| MySQL 连接池等待 | 应用日志 | 无 `PoolExhausted` |
| AI 路由成功率 | `ai_interactions` 总数 vs 失败日志 | ≥ 95%（生产） |
| 想法捕获数 | `ideas.created_at` 今日 | 业务自定 |

### 11.3 性能基线

| 路由 | 预期耗时 |
|------|---------|
| `GET /api/ideas` | < 100 ms（命中索引） |
| `POST /api/ideas` | < 50 ms |
| `GET /api/ai/*`（除 analyze/profile） | 2-10 s（含 AI 推理 + 重试） |
| `POST /api/ai/analyze` / `profile` | 5-20 s（多轮推理） |

> 性能基线以本地 + 默认模型为准；切到慢模型或大批量数据时按比例放宽。

### 13.2 启动顺序

```
spark-mysql (MySQL 8)
    ↓ 就绪后
schema.sql 初始化
    ↓ 就绪后
spark-web (Next.js standalone)
    ↓ 监听 3000
reverse proxy (nginx)
    ↓ 监听 443
公网
```

依赖关系：spark-web → spark-mysql → reverse proxy → 公网；上线时按依赖顺序启动。

### 13.3 常用运维命令速查

```bash
# 查看 spark-web 实时日志
docker logs -f spark-web

# 进入容器调试
docker exec -it spark-web sh

# 重启
docker restart spark-web

# 数据库交互
docker exec -it spark-mysql mysql -uroot -pspark123 spark

# 数据导出
docker exec spark-mysql sh -c 'mysqldump -uroot -pspark123 spark' > spark-$(date +%Y%m%d).sql

# 镜像清理（保留 spark-web:<tag> 与 spark-mysql:<tag>）
docker image prune -f
```
